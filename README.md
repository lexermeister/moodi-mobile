# Moodi

Moodi is an Expo/React Native application. The first milestone records M4A/AAC audio locally, keeps a persistent recording library, and supports playback, export, and deletion.

## Requirements

- macOS with Xcode and an iOS Simulator for local iOS development
- Node 24.3 or newer
- npm (the committed lockfile is `apps/mobile/package-lock.json`)

## Setup and checks

```bash
cd apps/mobile
npm ci
npm run typecheck
npm run lint
npm run doctor
```

The development iOS bundle identifier is `com.moodi.app.dev`. Native projects are generated by Expo and deliberately ignored:

```bash
cd apps/mobile
npx expo prebuild --platform ios --clean
npx expo run:ios
```

Use `npx expo run:ios` for the initial development build. Later JavaScript-only changes can use `npm start` with the installed development client.

## Manual iOS Simulator checks

1. Launch the local development build and tap **Record**.
2. Allow microphone access and confirm the button changes to **Stop**, elapsed time advances, and the simulator does not sleep.
3. Stop the recording. Confirm **Saved** appears only after finalization and the item is listed with a date and duration.
4. Play and stop the saved item, export it through the share sheet, then relaunch the app and confirm it remains listed.
5. Start recording and send the app to the background. Return and confirm recording was explicitly stopped and the finalized file is listed (or an error is shown if finalization was interrupted).
6. Delete an item, relaunch, and confirm it stays deleted.
7. Reset microphone permission in Simulator settings, deny access, and confirm Moodi shows denial guidance and an **Open Settings** action when iOS no longer permits another prompt.

In development, each verified file URI is logged as `[Moodi] Saved recording: ...`. The simulator container can also be inspected from Xcode or with `xcrun simctl get_app_container booted com.moodi.app.dev data`.

If recording remains on **Preparing microphone…** and Core Audio reports no input device, allow microphone access for Xcode/Device Hub in macOS Privacy & Security, select a Mac audio input for the simulator, and relaunch the development build.

## Physical iPhone checks

Before release, repeat recording with the built-in microphone and wired/Bluetooth audio routes on a physical iPhone. Verify interruptions from calls, Siri, alarms, route changes, the hardware silent switch during playback, the share sheet, and behavior while the device locks. Call and route-change behavior cannot be validated faithfully in the Simulator.
