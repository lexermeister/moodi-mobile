# Moodi

Moodi is an Expo/React Native application. It records M4A audio locally, keeps a persistent
recording library, uploads recordings to the Moodi backend, and displays completed transcripts.

## Requirements

- macOS with Xcode and an iOS Simulator for local iOS development
- Node 24.3 or newer
- npm (the committed lockfile is `apps/mobile/package-lock.json`)

## Setup and checks

```bash
cd apps/mobile
npm ci
npm run typecheck
npm run lint
npm run doctor
```

Configure the backend URL from `apps/mobile`:

```bash
cp .env.example .env.local
```

For the iOS Simulator, the default value connects to a backend running on the same Mac:

```dotenv
EXPO_PUBLIC_API_URL=http://127.0.0.1:8000
```

`EXPO_PUBLIC_API_URL` is included in the app bundle and must never contain a secret. The OpenAI
API key belongs only in the backend `.env` file.

The development iOS bundle identifier is `com.moodi.app.dev`. Native projects are generated by Expo and deliberately ignored:

```bash
cd apps/mobile
npx expo prebuild --platform ios --clean
npx expo run:ios
```

Use `npx expo run:ios` for the initial development build. Later JavaScript-only changes can use `npm start` with the installed development client.

## Manual iOS Simulator checks

1. Launch the local development build and tap **Record**.
2. Allow microphone access and confirm the button changes to **Stop**, elapsed time advances, and the simulator does not sleep.
3. Stop the recording. Confirm **Saved** appears only after finalization and the item is listed with a date and duration.
4. Confirm its state changes from **Uploading…** to **Transcribing…** and then **Transcribed**.
5. Confirm the transcript appears beneath the recording and remains after relaunching the app.
6. Stop the backend or use an invalid URL, create a recording, and confirm **Retry** is available.
7. Restore the backend, tap **Retry**, and confirm transcription completes.
8. Play and stop the saved item, export it through the share sheet, then relaunch the app and confirm it remains listed.
9. Start recording and send the app to the background. Return and confirm recording was explicitly stopped and the finalized file is listed (or an error is shown if finalization was interrupted).
10. Delete an item, relaunch, and confirm it stays deleted locally.
11. Reset microphone permission in Simulator settings, deny access, and confirm Moodi shows denial guidance and an **Open Settings** action when iOS no longer permits another prompt.

## Backend integration

Start the backend before launching the mobile app:

```bash
cd /path/to/moodi-backend
uv run uvicorn app.main:app --reload
```

After every newly finalized recording, the app:

1. Keeps the verified M4A file in app document storage.
2. Uploads it to `POST /recordings` as multipart field `file`.
3. Calls `POST /recordings/{id}/transcription` using the returned backend ID.
4. Saves the transcript, detected languages, backend ID, status, and retry error in the local
   recording index.

Existing local recordings show a **Transcribe** action. Failed requests show **Retry**. If the app
closes during upload or transcription, the interrupted state becomes retryable on the next launch.

For a physical iPhone, `127.0.0.1` refers to the phone itself. Use an HTTPS development URL or a
backend URL reachable from the phone instead, then fully reload the app after changing `.env.local`.

In development, each verified file URI is logged as `[Moodi] Saved recording: ...`. The simulator container can also be inspected from Xcode or with `xcrun simctl get_app_container booted com.moodi.app.dev data`.

If recording remains on **Preparing microphone…** and Core Audio reports no input device, allow microphone access for Xcode/Device Hub in macOS Privacy & Security, select a Mac audio input for the simulator, and relaunch the development build.

## Physical iPhone checks

Before release, repeat recording with the built-in microphone and wired/Bluetooth audio routes on a physical iPhone. Verify interruptions from calls, Siri, alarms, route changes, the hardware silent switch during playback, the share sheet, and behavior while the device locks. Call and route-change behavior cannot be validated faithfully in the Simulator.
